## Session 1, continued — can the official pymc-extras serve as the exact reference?

**Goal:** Opher asked for a strategy for using the lab's `pymc_extras` state-space model,
and whether the official, up-to-date pymc-extras meets our needs. Read-only.

**Findings:**
- **Correction.** The journal of 2026-10-01 and PR #13 said PyMC's ready-made state-space
  models cannot be used with the pinned PyMC 6.3. That was true of pymc-extras 0.14.0
  and is false now: 0.15.0 (2026-09-13) and 0.15.1 (2026-09-16) require
  `pymc >=6.3,<6.4` and `pytensor >=3.3,<3.4`, and are on conda-forge
  (`pixi search pymc-extras`; PyPI metadata). The claim was taken from a reference note
  and not checked against the package index.
- The lab repository `state-space-models` does not use the official package. Its
  `pixi.toml` installs pymc-extras from the fork `opherdonchin/pymc-extras@main`, and its
  lock file is at PyMC 5.26.1, PyTensor 2.35.1, Python 3.13, ArviZ 0.22.
- The fork is 6 commits ahead of and 137 behind `pymc-devs/pymc-extras` (merge base
  2025-11-02). It changes `statespace/core/statespace.py` and
  `statespace/utils/data_tools.py` to give `PyMCStateSpace` a `name` and a
  `register_variable` method, so that several state-space models (one per subject) can
  live in one PyMC model. Upstream: PR #611 closed unmerged; PR #654 ("Named
  StateSpaceModel v2") open, changes requested 2026-04-06, last activity 2026-05-01.
- Official 0.15.1 has neither `name` nor `register_variable`, refuses a second
  state-space graph in the same PyMC model, and requires time-varying matrices to be
  declared (`ssm.declare_time_varying(...)`), which the lab code does not do.
- GitHub reports `Motor-Learning-Lab/state-space-models` as private; the fork is public.

**Results** (one-off, in a throwaway environment made with `pixi exec`, PyMC 6.3.1 and
pymc-extras 0.15.1; script not kept): a `PyMCStateSpace` subclass for the one-state
model in the convention of decision 0005, vision flag included, gives the same
log-likelihood as a direct Kalman recursion and as the brute-force joint Gaussian, to
between 1e-6 and 3e-4 in absolute value, on four sittings of 12 to 300 trials. The two
hand calculations agree with each other to all printed digits; the remaining difference
is consistent with the package's default covariance jitter (1e-8).
