**Findings:**
- The model in decision 0002 is equations 1 to 4 of van der Vliet et al. (2018) up to
  the sign convention of the error (`p - y` here, `y + p` there). The lab code adds a
  `vision` flag that switches the learning rate off on no-vision trials, and has a free
  first state.
- In the paper the two noises were separated with 900 trials, 275 without vision. The
  weak identification of the noise ratio found on 2026-10-01 belongs to our schedule
  generator (45 to 320 trials, all with vision), not to the model. The sentence in
  decision 0002 saying the two are "only weakly identifiable" is too general.
- The lab code computes the likelihood with the `pymc_extras` forward Kalman filter,
  which supports the answer to "is a forward pass enough?" (yes for the parameter
  likelihood; the backward pass is for state estimates).
- GitHub does not draw `\operatorname` (probable cause of the math error Opher saw in
  decision 0002). `gh api markdown` cannot detect this, because the math is drawn in the
  browser.
- Decision 0002 was changed and set to Accepted directly on `main` on 2026-10-01, so it
  could not be commented on in a pull request. `docs/process.md` allows durable-state
  files on `main` but also puts decision records on the read track; the two conflict.
