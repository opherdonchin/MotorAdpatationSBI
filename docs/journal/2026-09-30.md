**Findings worth remembering:**
- **BayesFlow vs HSSM numpy conflict:** BayesFlow ≥ 2.0.13 needs `numpy>=2.5.1`; HSSM
  0.5.0 needs `numpy<2.5`. Filed as #4, to decide when HSSM work starts.
- **Seeding BayesFlow simulators:** `bf.make_simulator` has no `rng` argument and
  rejects `functools.partial` (it reads the function signature to route inputs). Simulator
  functions should close over a `np.random.Generator` spawned from the root seed.
  `sample_parallel` reseeds any generators it finds this way, so the AGENTS.md seed
  practice still holds.
- **`CouplingFlow` on a single parameter fails to build** ("Unable to automatically
  build the model"): with one dimension half the coupling layers are never used. Not a
  version problem (reproduced with Keras 3.15.0 too). Use `FlowMatching` (the
  recommended default) or have ≥ 2 inference variables.
- **PyMC multiprocess sampling after JAX is imported** warns that `os.fork()` can
  deadlock. The test uses `cores=1`. For notebooks, decide between `cores=1`, a
  non-fork multiprocessing context, or the nutpie sampler (recommended by the
  `bayesian-workflow` skill; not installed yet).

**Decisions:**

- JAX CUDA builds from conda-forge (not PyPI `jax[cuda12]`), declared through

- Pins: fast-moving packages pinned to a minor version in the manifest (`jax 0.10.*`,
  `keras 3.15.*`, `pymc 6.3.*`, `arviz 1.3.*`), BayesFlow to an exact version; the lock
  pins everything exactly.
- Simulators are packaged alongside `motor_sbi` in one distribution (hatch `packages`),
  so notebooks can `import simulators` without path hacks.
